# 学习打卡表 v3.0.0 方案：A 数据主权 + B 回顾统计

> 版本定位：按你的版本规则，3.0.0 = 架构级改动（+1）。本版动的是「数据存在哪」和「数据怎么读回来」两件底层事，不是加个按钮。
> 状态：**已实现（2026-11-04）**。三项决策均按推荐值落地：附件上云、打印 PDF + CSV、学期 = 2026-10 ~ 2027-06。
> 实现差异说明：附件未走对象存储，改为 `checkin_attachment` 表存压缩后 base64（主键 code+att_id，按需拉取）——SDK 对象存储需要建 bucket、权限链路更长，附件表方案更稳，效果等价（图片已压缩到长边 1280 / JPEG 0.82）。

---

## 一、现状盘点（事实，非推测）

| 项目 | 现状 | 结论 |
|---|---|---|
| 云端表 | `checkin_state(id, code, done jsonb, created_at, updated_at)` | 只存勾选状态 |
| 云端函数 | `merge_checkin(p_code, p_added, p_removed)` 服务端行锁原子合并 | 勾选多设备不冲突 |
| 本地存储 | `checkin:<月>:done:v1`（勾选）、`checkin:<月>:entries:v1`（自定义层）、`checkin.reminder.v1`（提醒）、`checkin.theme.auto.v1`（深浅）、`checkin.examNotified.v1` 等 | 自定义层/附件/提醒**仅本机** |
| 自定义层结构 | `{deleted:{k}, edited:{k}, att:{id:[{name,type,data}]}, custom:[{id,date,label,time,type}]}` | `att.data` 是 base64 图片，随条目存本地 |
| 现有统计 | 只有当月「已完成/总数/完成率/全勤天数」 | 无历史趋势、无跨月回顾、无导出 |
| SDK 能力 | 已确认 `database`（rest + rpc）与 `storage`（上传/签名 URL）都在 | 附件上云技术上可行 |

**核心缺口**：换手机 / 清缓存 / 换浏览器 → 勾选能回来，但**自定义条目、改名、角标、图片附件、提醒设置全部丢失**，得重配。这正是「数据主权」要解决的。

## 二、A：数据主权（全量上云）

### 2.1 数据模型（新增）

```sql
-- 1) 用户档案：自定义层 + 提醒设置，按月分片存 jsonb
create table checkin_profile (
  code       text primary key,
  entries    jsonb not null default '{}'::jsonb,  -- { "2026-11": {deleted,edited,custom,attMeta}, ... }
  reminder   jsonb not null default '{}'::jsonb,  -- {on,time,days,examOn,examAdv}
  rev        bigint not null default 1,
  updated_at timestamptz not null default now()
);

-- 2) 附件元信息（图片本体进对象存储，表里只留指针）
create table checkin_attachment (
  code         text not null,
  att_id       text not null,
  month        text not null,
  name         text,
  mime         text,
  bytes        int,
  storage_path text,          -- checkin-att/{code}/{att_id}
  created_at   timestamptz not null default now(),
  primary key (code, att_id)
);

-- 3) 历史快照（回滚用，保留最近 20 次）
create table checkin_profile_history (
  id bigserial primary key,
  code text not null,
  entries jsonb not null,
  rev bigint not null,
  saved_at timestamptz not null default now()
);
```

服务端函数 `merge_profile(p_code, p_patch jsonb, p_base_rev bigint)`：行锁 → 按「月分片 + 字段」做 LWW（last-write-wins）合并 → `rev = rev + 1` → 写一条 history → 返回合并后的完整 profile 与新 rev。

### 2.2 冲突策略（明确定义，不留模糊）

- 粒度：**「月 × 字段」级**，不是整表覆盖。设备 A 改了 11 月条目名、设备 B 删了 12 月某个任务 → 两者都保留。
- 同时改**同一字段**：以 `updated_at` 更晚者为准（服务端时间），另一台下次拉取时被覆盖，并在状态条提示「已合并 N 处他人修改」。
- 删除是「墓碑」：`deleted{k:1}` 也参与合并，避免被另一台复活。
- 每次合并写 history，设置页可「恢复到上一个版本」。

### 2.3 附件上云

- 上传前本地压缩：长边 ≤ 1280px、JPEG 质量 0.82，单张目标 ≤ 300KB（现在是原图 base64，一张动辄 1–2MB）。
- 存储路径 `checkin-att/{code}/{att_id}`，读取用短签 URL（默认 1 小时）。
- 失败降级：上传失败时保留本地 base64，条目上标「仅本机」，下次进站自动补传。
- 旧数据：v3 首次进站把已有本地附件批量补传（进度可见，可中断续传）。

### 2.4 迁移与兼容

- 首次进站：云端无 `checkin_profile` → 用本地 `entries` 初始化（一次性，标记 `checkin.profile.migrated.v1`）。
- **只加不删**：`checkin_state.done` 结构与 `merge_checkin` 完全不动，v2.7.x 老客户端继续能正常勾选。
- 换设备/清缓存：带 `?code=` 打开即全量恢复（勾选 + 自定义 + 附件 + 提醒）。

### 2.5 隐私边界（需要你知情）

打卡码就是唯一钥匙，拿到码就能读写全部数据 —— 附件上云后，**码的保密等级从「进度」升到「孩子的照片」**。对策：附件 URL 不长期有效、不带码的分享链接看不到附件、设置页可一键「清空云端附件」。

## 三、B：回顾统计

### 3.1 统计口径（先定死，避免数字对不上）

| 指标 | 定义 |
|---|---|
| 完成率 | 已完成任务数 ÷ 当月任务总数（总数由模型实时计算，不写死） |
| 连续打卡 | 连续「当日全部完成」的天数；今天已完成则从今天回溯，否则从昨天回溯 |
| 全勤天数 | 当月「全部完成」的天数 |
| 热力图 | 每日完成率分 5 档（0 / 1–25 / 26–50 / 51–75 / 76–100%） |
| 类型分布 | 按角标 考/课/作/复/补/无 统计任务条数占比 |
| 学期汇总 | 2026-10 ~ 2027-06 九个月逐月完成率 |

### 3.2 新增视图

1. **趋势**：近 8 周每周完成率柱状 + 连续天数徽章。
2. **热力图**：当月日历式色块，深色模式同步适配。
3. **月度报告**：整屏报告页 —— 大数字（完成率/全勤/连续天数）+ 类型分布 + 热力图 + 一句自动评语（按完成率阈值，非 AI 生成）。
4. **学期总览**：九个月逐月柱状，可点进任意月。

### 3.3 导出

- **PDF**：报告页走 `@media print` 专用样式，浏览器「打印 → 存储为 PDF」，中文字体与分页已处理，不依赖第三方库。
- **CSV**：逐日明细（日期、任务名、角标、是否完成、完成时间），Excel 可直接打开（带 BOM 防中文乱码）。
- 导出入口放「更多操作」与设置页「数据」区。
